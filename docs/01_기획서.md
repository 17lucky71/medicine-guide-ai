# 기획서 - medicine-guide-ai

노인을 위한 약 정보 안내 AI 서비스 (OCR 기반 복약 안내)

- 팀: 최영진, 장보윤, 이채리 (3명)
- 작성 기준: 2026-10-22 (기획 회의 10/5, 10/6, 10/13 내용 반영)
- 상태: 기획 단계 문서이며, `(확정 필요)` 표시는 팀 합의 후 수정한다.

---

## 1. 문제 정의

### 1.1 해결하려는 문제
병원·약국에서 받은 약봉투는 약 이름이 어렵고, 복용법과 주의사항이 작은 글씨로 적혀 있다.
이미 복용 중인 약이 있는 상태에서 새 약을 받으면, 함께 먹어도 되는지 스스로 확인하기 어렵다.

### 1.2 왜 노인인가
- 복용하는 약의 종류가 많아 중복 복용과 약물 상호작용에 노출되기 쉽다.
- 작은 글씨와 복잡한 설명을 읽기 어렵고, 앱 조작에 익숙하지 않은 경우가 많다.
- 자녀·보호자가 멀리 있어 복약 상태를 함께 확인하기 어렵다.

### 1.3 기존 서비스 분석
| 서비스 | 확인한 특징 (앱 소개 기준) | 우리 서비스와의 차이 |
|---|---|---|
| 아이약 (제안: 장보윤) | 처방전·약봉투 촬영 인식, 약 안전성 확인, 약 알람·복약 기록 | 노인 사용자 중심 화면(큰 글자·단순 구성)과 보호자 공유에 초점 (확정 필요) |

- 위 내용은 앱스토어 소개 문구를 바탕으로 한 것이며, 직접 사용해 본 뒤 장단점을 보강한다.
- 처방전 QR 바코드로 처방 정보를 입력하는 방식도 약국 현장에서 쓰이지만, 업체별 형식이 달라
  이번 프로젝트에서는 사진 인식 방식을 우선 적용한다. (향후 개선 과제)

## 2. 타깃 사용자
| 구분 | 설명 |
|---|---|
| 1차 사용자 | 여러 약을 복용하며 약봉투 내용을 이해하기 어려운 노년층 |
| 2차 사용자 | 노년층의 복약을 함께 확인하는 자녀·보호자 |

- 실사용자 테스트: 과정 담당자의 허락을 받아 팀원 3명(최영진, 장보윤, 이채리)이 각자 기기에서 진행, 가명 T1, T2, T3으로 기록

## 3. AI 활용 방식

### 3.1 사용하는 필수 기술 요소 (2개 이상)
| 기술 요소 | 서비스 안에서의 역할 |
|---|---|
| 멀티모달 AI | 약봉투 사진을 이미지 입력으로 받아 이미지를 이해할 수 있는 모델이 약 이름·용량·복용법을 추출 |
| Long-term Memory | 사용자별 복용 중인 약 정보를 저장해 두고, 다음 세션에서 새 약을 촬영하면 저장된 약과 비교해 안내 |
| (선택) RAG | 공공 의약품 정보(예: 식약처 의약품 정보 API)를 검색해 안내 문구의 근거로 활용 — 가능 여부 확인 후 결정 |

### 3.2 핵심 흐름
1. 사용자가 약봉투 사진을 올린다.
2. 멀티모달 모델이 이미지를 해석해 약 이름·용량·복용법을 구조화된 결과로 돌려준다.
3. 사용자가 결과를 확인·수정한 뒤 저장한다.
4. 저장된 복용 약 목록(Long-term Memory)은 다음 방문에서도 유지된다.
5. 새 약을 촬영하면 저장된 약 목록과 함께 모델에 전달해 중복·주의사항을 쉬운 말로 안내한다.
6. 모든 AI 안내에는 "AI가 생성한 참고용 정보이며 의사·약사 상담을 대체하지 않음"을 표시한다.

> 구현 시 주의: 이미지를 문자로만 바꿔 모델에는 텍스트만 넘기는 방식(예: OCR 엔진만 사용)은
> 평가 기준상 멀티모달 AI로 인정받지 못할 수 있다. 이미지 자체를 모델의 입력으로 사용하도록 설계한다.

## 4. 기술적 접근 방식

### 4.1 기술 스택 (확정 필요)
| 구분 | 제안 | 선정 이유 |
|---|---|---|
| 백엔드 | Python, FastAPI | AI API 연동 코드가 간결하고, 이미지 업로드·REST API 구현이 쉽다 |
| 프론트엔드 | React | 큰 글자·단순 화면을 컴포넌트로 재사용하기 쉽다 |
| AI | 이미지 입력을 지원하는 LLM API (예: OpenAI GPT-4o 계열) | 사진을 직접 이해해 정보를 구조화하고, 쉬운 말로 설명 생성까지 한 번에 처리 |
| DB | SQLite 또는 PostgreSQL (확정 필요) | 사용자별 복용 약 목록(Long-term Memory) 저장 |
| 배포 | 백엔드/프론트엔드 호스팅 서비스 (확정 필요) | 외부에서 접근 가능한 URL 필요 |

### 4.2 보안·윤리
- API 키는 `.env`에만 두고 저장소에 올리지 않는다 (`.gitignore` 적용).
- 서비스 화면에 AI 생성 콘텐츠임을 명시한다.
- 개인정보(복용 약 정보 등)를 저장하기 전 동의를 받는다.
- 테스터의 이름·연락처는 저장소에 올리지 않고 가명으로 기록한다.
