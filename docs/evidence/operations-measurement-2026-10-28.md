## Gemini 전체 분석 경로 측정

- 측정 도구: [Gemini 분석 측정 스크립트](../../scripts/measure-gemini-analysis.ps1)
- 원본 응답시간·상태 CSV: [Gemini 분석 측정 로그](gemini-analysis-latency-2026-10-28.csv)
- 측정 방식: 프로덕션 `/api/analyze`에 개인정보 없는 합성 약봉투 이미지 또는 `Tylenol` 텍스트 검색을 전송하고 HTTP 응답 시점까지 `curl`로 측정했습니다. 응답 본문은 저장하지 않았습니다.
- 사진 경로 성공 응답 3건: 평균 4.954초, 중앙값 4.358초, 범위 4.215–6.289초. 첫 세 차례 사진 요청은 HTTP 502였고, 이후 세 차례는 HTTP 200이었습니다. 이전 502의 Gemini 상위 상태 코드는 확보하지 못해 원인을 단정하지 않습니다.
- 텍스트 경로 성공 응답 3건: 평균 5.774초, 중앙값 4.293초, 범위 3.173–9.855초.
- 요청 시간은 테스트 클라이언트부터 API 전체 응답까지의 시간입니다. 앱에서 사진을 선택하고 축소하는 시간은 포함하지 않습니다. 세 건 표본은 성능 보증이나 SLA가 아니며, 초기 502도 함께 원본 로그에 남겼습니다.

## 보안 설정 코드 검토

- Gemini 키는 `frontend/api/analyze.js`에서 서버 환경변수로 읽습니다. 브라우저 요청에 키를 넣지 않습니다.
- 사진 분석 전 동의를 받고, 클라이언트는 이미지를 줄여 분석 요청으로 보냅니다. 서버는 업로드 이미지를 파일로 저장하지 않습니다.
- 저장 약 이름은 브라우저 `localStorage`에만 둡니다. 서버 DB나 계정 기능은 없습니다.
- 입력 제한: 검색어 100자, 저장 약 목록 최대 30개 및 각 60자.
- 배포 응답 헤더는 [실제 헬스체크 기록](production-health-probe-2026-10-28.txt)에서 확인할 수 있습니다.

이는 코드와 실제 응답을 읽어 정리한 설정 검토이며, 침투 테스트·취약점 진단·개인정보 영향평가 결과가 아닙니다. 현재 공식 SLA는 설정되어 있지 않습니다.
