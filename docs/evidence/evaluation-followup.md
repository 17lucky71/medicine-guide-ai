## 다음으로 모을 운영 로그

Vercel 프로젝트의 배포 로그에서 `/api/analyze` 호출 사례를 확인해 아래 양식으로 기록합니다. 이번에 저장한 헬스체크 응답은 공개 운영 URL을 직접 호출해 받은 실제 응답이며, Vercel 로그 화면을 대신하지 않습니다. 정상 요청과 실패 요청이 실제로 있는 경우 각각 포함하고, 없는 오류를 만들어 기록하지 않습니다.

| 시각 (KST) | 환경/배포 | 경로·메서드 | 상태 코드 | 처리 시간 | 요청 ID | 결과 요약 |
|---|---|---|---:|---:|---|---|
| (실제 로그에서 기입) | (Production/배포 ID) | `/api/analyze` · `POST` | | | | |

첨부 전에는 API 키, 요청 본문, 사진, 약 이름 등 건강 정보를 제거합니다. 평가 증거에는 비식별화한 로그 발췌와 Vercel 로그 화면 캡처를 함께 보관하고, 수집 시각과 조회 기간을 적습니다. 로그 조회 권한이 없거나 보존 기간이 지나 원본을 얻을 수 없다면 그 사실을 기록하고, 새 요청을 실제로 수행해 캡처합니다.

## 사용자 피드백 원본의 범위

제공된 Google Forms 요약 PDF에는 응답자 이름·연락처·연령·응답자 ID가 없습니다. 이 자료에는 개인 식별 정보를 추가할 필요가 없습니다. 다만 집계 요약만으로 참여자별 사용자 테스트 기록을 대신할 수는 없습니다. T3 개발자 테스트 자료는 별도 지시에 따라 마지막에 보완합니다.

## 남은 제출 항목

1. Vercel 대시보드의 실제 `/api/analyze` 운영 로그 캡처 또는 내보내기
2. GitHub Actions ESLint 실행 성공 화면/링크
3. AI 분석 전체 처리시간·장시간 가용률을 주장하려면 별도 실측 및 반복 모니터링 자료 (현재 수치만으로 SLA를 주장하지 않음)
4. T3 개발자 테스트 기록 (마지막 순서)
