# 기능 요구 명세서 - medicine-guide-ai

- 팀: 최영진, 장보윤, 이채리
- 작성 기준: 2026-10-22
- 상태: 2026-10-28 기준 구현·평가 문서. 실제 확인 결과와 미검증 목표는 구현 현황 및 [운영 측정 기록](evidence/operations-measurement-2026-10-28.md)에 구분해 적는다.

---

## 1. 개요
- 서비스명: medicine-guide-ai
- 목적: 노인 사용자가 약봉투 사진만으로 복약 정보를 이해하고, 복용 중인 약과 새 약을 비교해 주의사항을 확인하도록 돕는다.
- 대상 사용자: 노년층(1차), 자녀·보호자(2차)

## 2. 기능 요구사항

| ID | 기능명 | 설명 | 우선순위 |
|---|---|---|---|
| FR-01 | 약봉투 사진 업로드 | 카메라 촬영 또는 갤러리에서 약봉투/처방전 사진을 선택해 업로드 | Must |
| FR-02 | AI 이미지 해석 | 업로드한 이미지를 멀티모달 모델에 입력해 약 이름·용량·복용법을 구조화된 결과로 추출 | Must |
| FR-03 | 인식 결과 확인·수정 | 추출 결과를 확인 화면에 표시하고, 틀린 항목은 사용자가 직접 수정 후 확인 | Must |
| FR-04 | 복용 중인 약 저장 | 확인된 약 이름을 이 기기(브라우저)에 저장해 이후 방문에서도 유지 (Long-term Memory) | Must |
| FR-05 | 새 약 비교·주의사항 안내 | 새 약을 저장된 복용 약과 함께 모델에 전달해 중복·상호작용·부작용 주의사항을 쉬운 말로 안내 | Must |
| FR-06 | AI 생성·참고용 문구 표시 | 모든 AI 안내 화면에 AI 생성 콘텐츠이며 의사·약사 상담을 대체하지 않는다는 문구 표시 | Must |
| FR-07 | 개인정보 수집 동의 | 사진 업로드 전 동의 체크박스 표시(외부 AI 전송 안내 포함), 동의하지 않으면 업로드·분석하지 않음 | Must |
| FR-08 | 큰 글자 모드 | 글자 크기를 키우는 설정 제공 | Should |
| FR-09 | 가족 공유 | 복약 안내 결과를 링크로 공유 | Should |
| FR-10 | 복용 기록 조회 | 저장된 복용 약 목록과 날짜 조회 | Could |
| FR-11 | 로그인 | 사용자별로 복용 약을 저장·불러오기 위한 계정 로그인 | Could (현재 미구현, 향후 개선) |

- 현재 버전은 로그인 없이 사용하며, 복용 약은 사용자의 기기(브라우저)에 저장한다.
- Must 기능은 7개로 제한했다. (평가 시 Must 중 하나라도 동작하지 않으면 FAIL이므로 구현 가능한 핵심 기능만 Must로 둔다.)
- 아이약 참고 의견(장보윤)에서 나온 약 알람 기능은 Must에서 제외하고 향후 개선 과제로 둔다.

## 3. 비기능 요구사항

| ID | 항목 | 요구사항 |
|---|---|---|
| NFR-01 | 사용성 | 주요 화면은 큰 글자·큰 버튼·단순한 구성, 주의사항은 클릭 없이 바로 보이도록 표시 |
| NFR-02 | 응답 속도 | 합성 약봉투 사진의 전체 API 분석 응답은 성공 3건 평균 4.954초 (범위 4.215–6.289초). 표본이 작고 초기 502도 있어 보증 목표로 해석하지 않음. [측정 범위·원본](evidence/operations-measurement-2026-10-28.md) 참조 |
| NFR-03 | 개인정보 | 동의 후에만 저장, 이름·연락처 등 불필요한 개인정보는 수집하지 않음 |
| NFR-04 | 보안 | API 키 등 비밀 정보는 환경변수로 관리하고 저장소에 올리지 않음 |
| NFR-05 | 접근성 | 모바일 브라우저에서 사용 가능한 반응형 화면 |
| NFR-06 | 신뢰성 | AI 응답 형식 오류 시 기본 안내 문구("약사 또는 의사에게 문의하세요")를 표시 |
| NFR-07 | 가용성 | 공식 SLA 미설정. 짧은 헬스체크 관측을 지속 가동률 보장으로 해석하지 않음 |

## 4. 시스템 아키텍처

```
[사용자 브라우저 (React, Vercel 배포)]
        │ 1. 약봉투 사진 업로드 (브라우저에서 크기 축소 후 전송)
        ▼
[Vercel 서버리스 함수 /api/analyze]  ← GEMINI_API_KEY (서버 환경변수)
        │ 2. 이미지 + 저장된 복용 약 목록 → Gemini 2.5 Flash (멀티모달)
        │    약 이름·효능·복용법·주의사항 + 저장된 약과의 비교 문구 생성
        ▼
[브라우저: 결과 확인·수정(이름 수정/삭제) → 저장]
        │ 3. 확인된 약 이름을 localStorage(myMeds)에 저장 (Long-term Memory)
        ▼
[다음 방문/새 약 업로드 시 저장된 약 목록을 AI 요청에 함께 전달]
```

- 기술 스택: React(CRA), Vercel 서버리스 함수, Google Gemini 2.5 Flash.
- 이미지 파일은 서버에 저장하지 않고 분석 요청에만 사용한다 (저장소·DB 없음).
- 한계: 복용 약 목록은 사용자의 기기(브라우저)에만 저장되며, 기기를 바꾸면 보이지 않는다. 계정·DB 연동은 향후 개선 과제.

## 5. AI 활용 명세

| 기능 | AI 활용 방식 | 상세 설명 | 기술 요소 | 코드 위치 |
|---|---|---|---|---|
| FR-02 AI 이미지 해석 | 멀티모달 LLM | 약봉투 이미지를 모델 입력으로 전달해 약 이름·효능·복용법·주의사항 추출 (시스템 지시문에 추측 금지·개인정보 제외·줄 그어진 약 제외 규칙 포함) | 멀티모달 AI | frontend/api/analyze.js |
| FR-04 복용 약 저장 | Long-term Memory | 사용자가 확인한 복용 약 목록을 브라우저(localStorage)에 저장하고 다음 방문의 요청에 반영 | Long-term Memory | frontend/src/App.js (handleSaveMeds) |
| FR-05 비교·주의사항 | LLM + 저장된 기억 | 새 약 사진과 저장된 복용 약 목록을 함께 전달해 중복·주의사항을 쉬운 말로 생성 | Long-term Memory + 멀티모달 AI | frontend/api/analyze.js (savedMeds, comparison) |

- FR-05는 멀티모달 AI(새 약 사진 해석)와 Long-term Memory(저장된 복용 약 반영)가 함께 쓰이는 기능이다.
  Must 기능 중 필수 기술 요소 2개가 쓰이는 기능이 포함되어야 한다는 평가 기준을 이 기능으로 충족한다.
- 단순 API 1회 호출이 아니라, 저장된 사용자 정보가 다음 세션의 응답에 실제로 반영되도록 구현한다.

## 6. 구현 현황 표
평가자가 그대로 따라 할 수 있도록 화면·버튼·입력값을 적는다. 구현·확인이 끝난 뒤에 채운다.

| 기능명 | Must 여부 | 구현 여부 | 확인 방법 | 기대 결과 |
|---|---|---|---|---|
| FR-01 약봉투 사진 업로드 | Must | 구현·확인 (2026-10-22) | 배포 주소 접속 → 동의 체크 → [사진 선택] → 처방전/약봉투 사진 선택 | 선택한 사진 미리보기가 표시되고 AI 분석이 시작된다 |
| FR-02 AI 이미지 해석 | Must | 구현·확인 (2026-10-22) | 사진 선택 후 잠시 대기 ("사진을 AI가 읽고 있습니다") | 약 이름·효능·복용법·주의사항이 화면에 표시된다 |
| FR-03 인식 결과 확인·수정 | Must | 구현·확인 (2026-10-22) | 결과 화면에서 약 이름 칸 수정 또는 [이 약 삭제] 클릭 | 수정·삭제한 내용이 반영되고, 저장 시 수정한 이름이 저장된다 |
| FR-04 복용 중인 약 저장 | Must | 구현·확인 (2026-10-22) | 결과 확인 후 [확인한 약을 복용 중인 약으로 저장] 클릭 | "내가 복용 중인 약" 목록에 표시된다. 같은 기기·브라우저에서 다시 접속해도 유지 (재접속 확인은 팀 테스트에서 기록) |
| FR-05 새 약 비교·주의사항 안내 | Must | 구현·확인 (2026-10-22) | 저장된 약이 있는 상태에서 다른 처방전/약봉투 사진 업로드 | 결과 상단 "저장된 약과 비교" 박스에 비교 안내가 표시된다 |
| FR-06 AI 생성·참고용 문구 표시 | Must | 구현·확인 (2026-10-22) | 첫 화면 상단 노란 띠, 결과 카드 하단, 페이지 하단 확인 | AI 생성 참고용이며 의사·약사 상담을 대체하지 않는다는 문구가 표시된다 |
| FR-07 개인정보 수집 동의 | Must | 구현·확인 (2026-10-22) | 첫 화면의 동의 체크박스 확인 | 체크해야만 사진 업로드가 진행된다 (미체크 시 안내) |
| FR-08 큰 글자 모드 | Should | 화면 버튼 확인 (동작 재확인 필요) | 상단 [기본/크게/특대] 버튼 클릭 | 화면 글자 크기가 바뀐다 |
| FR-09 가족 공유 | Should | 미구현 | (배포 후 작성) [가족에게 공유] 버튼 | 공유 링크가 생성된다 |
| FR-10 복용 기록 조회 | Could | 미구현 | (배포 후 작성) | (배포 후 작성) |
| FR-11 로그인 | Could | 미구현 | - | 이번 범위 아님 (향후 개선 과제로 이동) |

## 7. 향후 개선 과제 (이번 범위 아님)
- 약 알람 및 복약 기록 알림
- 처방전 QR 바코드 스캔을 통한 처방 정보 입력
- 공공 의약품 정보 API 연동으로 상호작용 정보 보강
- 음성 안내(TTS)
